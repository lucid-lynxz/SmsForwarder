# 通知监听去重

APP 通知（尤其微信）常对**同一条消息**先 post 再 update：一次给摘要、一次给全文，update 时还可能在前面补群名。旧版会把这条消息转发两遍，现在同一条只转发一次。

## 行为

- 判定「同一条通知」需同时满足三点：**同一条通知的 key**（包名 + tag + id + userId）、**间隔在 3 秒内**、**内容视为同一条消息**。
- 内容比对是**模糊**的：先去掉所有空白和结尾省略号，再判断「完全相同」或「一方包含另一方」。为避免误杀，**归一化后长度不足 10 个字符的短消息不做包含判定**（「收到」/「收到，好的」这类不会被吞掉）。通知标题不参与比对。
- 命中重复后**静默跳过**：不转发、不写消息记录、不写转发日志，只有 logcat 里一条 debug 日志。所以「日志里查不到」是预期表现，不是转发失败。
- 去重状态在内存中，最多跟踪 64 条通知（超出按最旧淘汰）；**APP 进程被杀后状态丢失**，此时 post 与 update 会各转发一次。

## 与旧「过滤重复消息」的区别

两者互相独立、同时生效：

| | 通知监听去重（本次新增） | 通用设置 → 自动过滤多久内重复消息（原有） |
| --- | --- | --- |
| 判定依据 | 通知 key + 3 秒内 + 内容模糊比对 | 类型 + 来源 + 内容 **精确** md5 |
| 范围 | 仅 APP 通知监听 | 短信 / 通话 / APP 通知 |
| 时长 | 固定 3 秒 | 用户设置，`0` = 禁用 |
| 可否关闭 | 不能，无开关 | 可（设为 0） |

**短信、通话的重复上报仍要用通用设置里的那个参数处理**（提示文案：`0=禁用，判断重复：类型+来源+内容`）。

## 注意事项

1. **3 秒窗口不可配置、不可关闭**。同一会话里 3 秒内连发的两条相同长消息（≥10 字符且互为包含），会被判定为重复而只转发第一条。
2. **自动任务的触发时机有变化**：原有的「过滤重复消息」判断已移到自动任务处理**之前**。开启该过滤后，被判定重复的消息**不会再触发自动任务的条件与动作**（此前可能先触发自动任务、再被规则通道拦下）。
3. 手动点「重新匹配」是用户主动行为，带有跳过重复过滤的标记，不会被上述机制拦掉；但日志页的「重试」本就不走该过滤。
4. 去重发生在关键词黑名单等已有过滤之后、消息入库之前。
