# 允许转发时间窗口

给**转发规则**限定转发时段：规则命中后，只有当前时间落在该规则勾选的任一窗口内才转发，否则整条规则跳过。

## 入口

- 管理窗口：侧边栏 → **转发规则** → 标题栏「时钟」图标 → 允许转发时间窗口 → 右上角「+」
- 绑定到规则：转发规则 → 编辑某条规则 → **允许转发时间窗口**（位于「规则状态」开关与「免打扰」之间，多选标签）

## 窗口字段与语义

| 字段 | 说明 |
| --- | --- |
| 窗口名称 | 仅要求非空，不校验重复（重名会让规则页的标签难以区分） |
| 允许转发的星期 | 周一~周日多选；**一个都不勾 = 每天** |
| 允许转发的时间段 | 起止时间；**结束早于开始 = 跨天**（如 22:00~02:00）；**结束等于开始 = 全天**（默认即 00:00~24:00） |

- 判定**含起点、不含终点**，因此 `08:30~12:00` 与 `12:00~18:00` 两个相邻窗口不会重叠。
- 时间选择器只提供 `00:00`~`24:00` 每 **10 分钟**一档，选不到 `08:35` 这类时间。
- 窗口没有「启用」开关，也没有排序字段：存在即生效，列表按创建顺序（id）排列，不能手动调序。

## 生效逻辑

- 一个规则可以勾选**多个窗口，命中任一即放行**（OR 关系）；**一个都不选 = 始终转发**。
- 检查在消息**转发之前**、逐规则进行，位于全局「免打扰」判断之后、任何发送通道执行之前。命不中窗口时：
  - 该规则的**所有通道都不执行**（其它规则不受影响）；
  - **转发记录**里会留下一条状态为「失败」的记录，内容为：`当前时间不在允许转发时间窗口[窗口名]内，本规则已跳过`；
  - 消息本体仍已入库，可在日志页看到原文，之后用「重试」发出（见下方旁路）。
- 规则编辑页的**测试**按钮同样校验，窗口外会以错误提示直接返回。

## 注意事项

1. **星期 + 跨天的组合边界**：星期和时间段针对同一时刻判定，所以 `周一 / 22:00~02:00` **不覆盖**周二凌晨 00:00~02:00。需要覆盖凌晨那段，必须同时勾上「周二」。
2. **窗口被删光 = 停止转发**：若规则引用的窗口**全部**被删除，该规则不再转发（宁可不发，也不在错误时段发出），提示 `规则绑定的时间窗口不存在，本规则已跳过`。只删掉其中一个时，仍按剩余窗口判定。进入规则编辑页重新保存会自动剔除失效引用。
3. **两条旁路不校验窗口**：转发日志的「重试」、自动任务的「通知转发」动作，都在窗口外也能发出。
4. **新建窗口默认不过滤**：默认「每天 + 全天」，直接保存等于不限制时段，需要自行收紧。
5. 规则编辑页的窗口标签在进入页面时读取，编辑期间新建的窗口不会出现，需退出重进；一条规则**绑定哪些窗口只能进编辑页看**，规则列表卡片上不显示。
6. 窗口判定优先于通道级的规则免打扰设置，两者叠加时先被窗口拦下。

## 升级说明

数据库 v21→v22 创建 `TimeWindow` 表，v22→v23 给 `Rule` 增加 `time_window_ids`（逗号分隔的窗口 id 列表）。早期版本曾把窗口绑在**发送通道**上，现已改为绑在**转发规则**上；旧列 `Sender.time_window_id` 保留在库中但不再读写——minSdk 19 不支持 `DROP COLUMN`，而重建 `Sender` 表会因外键级联清空转发日志。
