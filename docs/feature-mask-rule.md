# 内容打码规则

在消息**发出之前**用正则替换/删除敏感内容。规则本身是一条条独立的打码策略，**发送通道**勾选要应用哪些规则。

## 入口

- 管理规则：侧边栏 → **发送通道** → 标题栏「打码」图标 → 内容打码规则 → 右上角「+」
- 绑定到通道：编辑任一发送通道 → 表单最后一组 **内容打码规则**（多选标签，位于「测试/删除/保存」按钮之前）

16 种通道（短信、邮件、Webhook、企业微信、钉钉、飞书、Bark、Telegram、Server酱、PushPlus、Gotify、Socket、URL Scheme 等）都支持绑定。

## 字段

| 字段 | 说明 |
| --- | --- |
| 规则名称 | 仅要求非空 |
| 启用 | 开关，默认开启；关闭后该规则被跳过，但**仍保留在通道的勾选里** |
| 匹配正则 | 例：`(\d{3})\d{4}(\d{4})`；保存时校验语法 |
| 替换文本 | 可用 `$1` 引用分组，例：`$1****$2`；**留空 = 直接删除匹配到的内容**（列表里显示为「删除匹配内容」） |
| 生效顺序 | 数字，越小越先执行；留空按 `0` 处理，只能输入非负数 |

## 生效逻辑

- **执行顺序由「生效顺序」决定，不是通道里的勾选顺序**。多条规则按 `生效顺序 → id` 依次链式执行，前一条的输出是后一条的输入。
- **区分大小写**，且替换**所有**匹配项（不是只替换第一个）。这与「转发规则」的匹配正则不同（后者忽略大小写）。
- 只处理**消息内容**：来源号码、卡槽、时间、通话类型等都不参与，也不会被打码。
- 打码发生在**自定义模板展开之前**：正则只能匹配原始短信/通知文本，模板里新增的文字或规则级正则替换的结果都匹配不到。
- **只有出站内容被打码，本机日志保留原文**。因此日志页「重试」「重新匹配」以及事后查看都是明文，不要把「日志里看到原文」当成打码失效。

## 注意事项

1. **多通道会叠加打码**：一条规则绑定多个通道时，第二个通道收到的是**已被第一个通道的规则处理过的内容**，可能出现二次打码（例如把已经是 `$1****$2` 的段落再打一遍）。若各通道需要不同处理，请拆成不同规则。
2. **通道编辑页的「测试」按钮不打码**，看到的是原文；规则编辑页的「测试」会走打码流程。以实际转发结果为准。
3. **规则被删除后按不打码发送**：通道引用的规则若已不存在或被禁用，转发**照常进行且内容不脱敏**，运行时也没有任何提示（`通道绑定的打码规则不存在，已忽略该规则` 这句文案只出现在规则编辑页）。删除打码规则前的确认弹窗就是这个风险。进通道编辑页重新保存会剔除失效引用。
4. **引用不存在的分组会在发送时抛错**：保存时只校验正则本身能否编译，不校验 `$1` 是否有对应分组。写错时该条规则当次生效失败（仅 logcat 记录），消息按未打码内容继续发送。
5. 想「先脱敏卡号再脱敏手机号」这类链式效果，请靠**生效顺序**编排，不要依赖勾选顺序。

## 升级说明

`MaskRule` 表在数据库 v21→v22 创建，同时给 `Sender` 增加 `mask_rule_ids`（逗号分隔的规则 id 列表），此后版本未再变更。配置导出/导入会带上打码规则；旧版备份里没有该段落时，导入会保留当前配置而不是清空。
