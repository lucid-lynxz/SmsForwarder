# 转发消息附带位置

给家里老人用的场景：他们不会主动发定位，但只要转发一条消息，就把手机当前所在位置一起带过去。**按来源应用逐个开关**（例如微信开、QQ 关）。定位改为**按需单次**：平时不常驻定位监听（系统状态栏/控制中心的隐私指示不会常亮），只有命中勾选、真正要附带位置时才发起一次定位，拿到坐标即停；缓存够新则直接复用，因此转发频繁也不会反复搜星。

## 入口

通用设置 → 打开「GPS定位服务」→ 展开区域最底部：

- **转发消息附带位置**：总开关，关闭时下方选择区隐藏。
- **选择应用**：点开是一个**多选列表**（每行一个应用名 + 勾选框），勾完点「保存」，开关下方直接显示「已选 N 个：微信、短信」这样的应用名，不需要手写包名。
  - 列表来自系统「有启动入口的应用」（`MAIN/LAUNCHER` 可解析），所以看到的是用户真正认得出的 APP，不会混进一堆系统服务；查询放在子线程，只取名称不加载图标。
  - 已保存但当前列表里找不到的包名（应用被卸载、或它本来就没有启动入口）会**追加在列表末尾**并显示包名，保证还能取消勾选。
  - 存储格式仍是 `append_location_apps` 里**一行一个包名**，与旧版本手写的名单完全兼容，匹配逻辑不变。
- **位置变化阈值 / 透出间隔**：两个数字输入框（米 / 分钟），默认 **200 米 / 30 分钟**，边改边存；清空或输入非法时保留已存值。任一填 0 = 不节流。
- **移动提醒阈值**（在 GPS定位服务 展开区域底部，不随「转发消息附带位置」开关隐藏）：数字输入框（米），默认 **500 米**，填 0 = 不提醒。它管的是位置块里那一行「较上次发出位置移动 …」，附带位置与 `{{LOCATION}}` 标签都生效。

开关行只在「GPS定位服务」开启时可见——没有定位服务就没有位置缓存，功能无从生效。

## 生效逻辑

三个条件同时满足才进入追加流程，否则原文发出：

1. 总开关开启；
2. 消息的**来源包名**精确匹配所勾选的应用（**大小写敏感、不支持前缀与通配**）；
3. 走的是普通文本模板渲染（`MsgInfo.getContentForSend`）。

进入追加流程后还要过**透出节流**（见下节）：被节流的消息同样原文发出、不带位置。

追加位置在**模板渲染完成之后**、发到通道之前，因此：

- 转发记录与日志页里保存的仍是**不含位置的消息原文**，只有实际发出去的内容带位置；
- 通道绑定的**内容打码规则**先执行，作用在消息本体上，位置文本既不会被打码，也不会参与打码的正则匹配；
- 「重试」是重新渲染，位置取的是**重试那一刻**的缓存，不是当初的坐标。

不追加的通道字段（有意排除）：

| 位置 | 原因 |
| --- | --- |
| Bark 的「URL」「自动复制」模板 | 这两个字段是链接/剪贴板内容，拼上整段位置会坏掉 |
| 飞书 App / 飞书自定义机器人的 JSON 卡片 | 走 `getContentFromJson`，输出结构化 JSON，末尾追加纯文本会破坏格式 |
| 标题（`getTitleForSend`） | 只作用于正文 |

## 透出节流（距离 + 时间双阈值）

消息本体往往只有一两行，每条都挂四行位置会很吵。命中勾选后**不是每条都透出**，满足其一才再次附带：

- 移动距离 ≥「位置变化阈值」（默认 200 米）；
- 距上次透出 ≥「透出间隔」（默认 30 分钟）。

都不满足时这条消息**不带位置**，收消息的人参考上一次的位置——这是节流唯一的代价，所以间隔别设太大。

- 距离按球面距离（haversine）算，比较的是缓存里的 WGS-84 原始坐标；GPS 抖动几米不算「位置变化」。
- **首次透出**、定位从「未就绪」恢复、或从有位置变回「未就绪」，都必透出一次：状态变化优先于阈值。
- 任一阈值填 **0 = 不节流**，回到每条都带。
- 节流状态（上次透出时间、坐标、消息键）存 SharedPreferences，**进程重启不丢**；整台设备共用一份，不按应用各算。
- **同一条消息**会在多个通道、重试里重复渲染。用「来源包名 + 接收时间」做消息键：键与上次透出相同就继续带位置，保证一条消息在各通道表现一致，也不会重复消耗节流状态。为此 `MsgInfo.smsVoForSend`（序列化/日志用原文）改为不带位置渲染，避免未命中规则的消息在构造时就消耗状态。
- 节流只控制末尾自动附带的那一段；模板里的 `{{LOCATION}}` 在命中勾选时始终被抹掉（见下节），不会因节流而「复活」。

## 追加内容长什么样

自动附带与模板里的 `{{LOCATION}}` 标签共用同一个位置块（`LocationUtils.buildLocationText`），只有「地图链接」的写法按通道形态分岔：

```
经纬度: 116.403672,39.910597 https://uri.amap.com/marker?position=116.403672,39.910597&coordinate=gaode&callnative=1
较上次发出位置移动 1.2 公里（40 分钟前）
地址: 北京市东城区xxx街道xxx路
采集于 2026-11-15 12:00:00（3 分钟前）
```

- **链接不再单独占一行**：纯文本通道把裸链直接接在经纬度后面同一行，短信/IM 靠系统自动识别裸 URL 仍可点。
- **支持富文本的通道把链接藏进经纬度**：钉钉群机器人 `msgtype=markdown`、企业微信机器人 `msgType=markdown`、钉钉企业内部机器人 `sampleMarkdown` 输出 `[116.403672,39.910597](链接)`；邮件正文按 HTML 发送，输出 `<a href="链接">116.403672,39.910597</a>`。这样企业微信 markdown（裸 URL 不自动识别）也能点，字数还更省。
  - 通道形态由发送方告诉渲染方：各 sender 调 `getContentForSend(..., linkStyle = ...)`，`LocationLinkStyle` 默认 PLAIN，未列出的通道（短信、Bark、飞书、webhook 等）行为不变。
  - **没有把链接藏起来的通道，是因为藏了就点不动**：纯文本通道里经纬度变成一串数字，走丢场景反而更糟。
- **坐标系**：系统定位回调给的是 WGS-84（GPS 原始坐标），这里已转成 **GCJ-02**（国测局/火星坐标），与高德、腾讯地图一致，点开链接不会偏出几百米。境外坐标不偏移（偏移算法只在国内有定义）。**要在 Google Maps 里看的话，这个值是偏的**，请改用 `{{LOCATION_LONGITUDE}}` / `{{LOCATION_LATITUDE}}` 拿原始坐标。
- **地址行**只有系统 Geocoder 返回结果时才出现（部分 ROM 或无 Google/厂商定位服务时可能始终为空，此时省略该行）。
- **地图链接**用的是 `uri.amap.com`，不需要 API key；装了高德 APP 会直接唤起，没装则在浏览器打开网页版。
- 经纬度固定按 `Locale.US` 格式化（6 位小数），避免某些语言环境把小数点输出成逗号导致链接参数失效。
- `{{LOCATION}}` 标签的输出与本文一致，**不再附带「供应商」那一行**；`LocationInfo.toString()`（日志、到/离地址任务描述用）是同一块的纯描述，不带移动提醒行。

## 移动提醒（走丢兜底的关键一行）

只靠「有消息才转发」，老人一整天不出门、不发消息就完全没有位置。把**定时任务**当心跳用即可：新建一个 CRON 自动任务（例如每 20 分钟一次），通道选钉钉/企业微信机器人，自定义模板里写 `{{LOCATION}}` —— 每次触发都会按需发起一次定位并发出位置块，这就是周期上报，不需要额外的轮询。

在这个块里，每条位置都会与**上一次实际发出的位置**比距离：

- 移动 ≥「移动提醒阈值」（默认 **500 米**，通用设置 → GPS定位服务 区域最底部，边改边存；填 **0 = 不提醒**）时，多出 `较上次发出位置移动 1.2 公里（40 分钟前）` 一行；没超过就不加这一行，保持精简。
- 收到通知的人因此同时拿到三个信号：**现在在哪**、**离上次见到他moved了多远**、**上次是什么时候发的**。括号里的时长用的是上次发出位置的时刻，不是本次定位时刻。
- 水位是独立的一份（`location_move_last_*`），**与附带位置的透出节流互不影响**：节流控制「要不要带位置」，水位只用来算距离。定时任务和 app 通知附带的位置共用同一份水位，所以不会因为两条链路各算各的而把距离算成 0 或翻倍。
- 首次上报（还没有水位）只铺基准、不出提醒；定位未就绪时**不推进水位**，避免把「室内读不到位置」记成「没动」。
- 同一条消息在多通道、重试里重复渲染时，第一次算出的距离会被复用（同样按「来源包名 + 接收时间」的消息键），各通道看到的移动提醒数字一致。
- 阈值与省电：提醒粒度取决于心跳频率。定时任务 20 分钟一次，那么「走丢」最迟 20 分钟 + 一次搜星（8 秒超时）后才能看见；间隔越短越及时，但每轮都会点亮一次系统隐私指示（按需单次定位，不会常亮）。

## 新鲜度与省电（按需单次定位）

- **不再常驻定位**：旧版「GPS定位服务」一直挂着定位监听（`setOnceLocation(false)` + 最小时间间隔周期回调），系统隐私指示因此常亮，看起来像「不需要时也在后台偷偷定位」。现在改为**按需单次**——`LocationService` 只持有监听与生命周期，平时不发起任何定位。
- **触发时机**：只有命中勾选、要附带位置的那次正文渲染（`LocationUtils.appendLocation`），或模板里写了 `{{LOCATION}}` 系列标签的渲染（`MsgInfo.replaceLocationTag`），才会调用 `ensureFreshLocation()` 按需刷新。没命中勾选、标题、Bark 的 URL/自动复制、飞书 JSON 卡片都不触发定位。
- **缓存够新就复用**：`ensureFreshLocation()` 先看 `apiLocationCache` 的采集时间，**60 秒内**视为新鲜直接复用，不再发起定位——同一条消息的多通道/重试、短时间内的多条转发都只定位一次。
- **单次定位 + 超时回退**：缓存过期才 `LocationService.requestLocationOnce(8000ms)`：设 `setOnceLocation(true)` 发起一次定位，`onLocationChanged` 拿到坐标即唤醒等待方并停止；**8 秒超时**或定位异常则回退已有缓存，不阻塞转发太久。并发调用串行化（共用一个 latch），不会重复搜星。定位动作派发到专用 `HandlerThread`——king-location 的 `startLocation` 要求调用线程有 Looper，而转发/测试跑在无 Looper 的 worker 线程；回调与 Geocoder 也在该线程，不占主线程。
- **只在后台线程定位**：`ensureFreshLocation()` 在主线程直接跳过，避免阻塞 UI 造成 ANR；转发渲染本就在 worker 线程，正常命中。
- **到/离地址自动任务**：仍由 `onLocationChanged` 在坐标/地址变化时触发，但现在只在「按需单次定位」拿到新坐标那一刻顺带评估，不再随持续定位周期性触发——没有转发需要位置时，这类任务不会自己跑。
- 位置旧了**照发**，并显式标注新鲜度：`采集于 …（刚刚采集 / N 分钟前 / N 小时前 / N 天前）`，收到的人能判断可信度。
- 缓存还没数据（进程刚重启且尚无转发触发定位、系统定位没开、室内搜不到星）时，发出的是 `[位置] 定位未就绪：请确认系统定位已打开，且已开启「GPS定位服务」`，而不是静默少发一段。缓存 `apiLocationCache` **存 SharedPreferences、落盘**，进程重启后仍保留上一次的坐标与采集时间。
- **「最小时间间隔 / 最小距离」两个滑块在按需模式下已不起作用**：单次定位用不到 `setMinTime/setMinDistance`，它们只在旧版持续定位里有意义；保留控件是为兼容旧配置，后续可考虑隐藏。`电量消耗`（默认「低」）与`精度`仍作用于单次定位的档位。

## 与已有 `{{LOCATION}}` 标签的关系

两者共用同一份定位缓存。**命中自动附带时，正文模板里的 `{{LOCATION}}` 会在渲染前被抹掉**，避免一条消息里出现两段位置（上游标签输出的是多行原始信息：经度/纬度/地址/时间/供应商）。

| | 附带位置（本次新增） | `{{LOCATION}}` 等标签（上游原有） |
| --- | --- | --- |
| 触发方式 | 勾选命中后自动追加到末尾 | 在自定义模板里手写标签，位置随你放 |
| 生效范围 | 勾选的**来源应用** | 所有消息（模板里写了就替换） |
| 坐标系 | GCJ-02（已偏移） | WGS-84 原始值 |
| 输出 | 经纬度 + 地址 + 采集时间 + 高德链接 | `{{LOCATION}}` 为多行原始信息；`{{LOCATION_LONGITUDE/LATITUDE/ADDRESS}}` 为单字段 |
| 定位未就绪 | 明确提示一行 | 经纬度替换成 `0.0` |

抹掉只发生在**会追加位置的那次正文渲染**：标题、Bark 的 URL/自动复制、飞书 JSON 卡片，以及没命中勾选的应用，`{{LOCATION}}` 照常替换。`{{LOCATION_LONGITUDE/LATITUDE/ADDRESS}}` 单字段标签也不受影响——要把原始坐标放进消息中间、或要 Google Maps 坐标时，仍然用这些标签。

## 注意事项

1. **只对 APP 通知来源生效**：勾选的是应用（存的是包名），而短信、通话记录的 `from` 是**手机号**，永远匹配不上。要给「短信」也带位置，请改用转发规则里的自定义模板 + `{{LOCATION}}` 标签。
2. **一个都没勾 = 一个都不附带**（不是「全部」），与总开关的语义一致：宁可少发。
3. **短信通道会被撑长**：位置块约 130~200 字符，其中地图链接就占 85+ 字符，一条短信很容易拆成 2~3 条或被运营商截断。给老人配置时优先用网络通道（微信/钉钉/飞书/PushPlus/Bark 等）。
4. **位置是敏感信息**：它会出现在转发目标、以及重试/测试时的预览里。只勾选真正需要的应用，别拿无关应用做「全量开启」的试验。
5. 需要已授予定位权限且系统定位开关打开；「GPS定位服务」若因系统定位不可用被自动关掉，本开关所在区域会一起隐藏，但**总开关与已勾选应用仍保留**——重新打开定位服务后无需再配一遍。
6. 「转发规则」页的**测试**按钮同样会追加位置（走 `SendUtils.sendMsgSender`，与真实转发同一条渲染路径），但测试弹窗里的「来源」必须填**勾选过的包名**（如 `com.tencent.mm`）才会命中——随手写个昵称就看不到位置。
